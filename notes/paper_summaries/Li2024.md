# Paper Summary: Li2024

-   **BibTeX Key**: Li2024
-   **Title**: Optimizing IoT intrusion detection system: feature selection versus feature extraction in machine learning
-   **Authors**: Jing Li, Mohd Shahizan Othman, Hewan Chen, and Lizawati Mi Yusuf
-   **Year**: 2024
-   **Publication Venue**: Journal of Big Data

---

## Research Objective
To conduct a comprehensive comparison of feature selection (FS) and feature extraction (FE) methods for building lightweight Network Intrusion Detection Systems (NIDS) tailored to IoT environments. The study aims to derive valuable guidelines for balancing detection accuracy and computational complexity by benchmarking these two techniques on modern IoT datasets.

## Problem Addressed
Internet of Things (IoT) devices are widely used but vulnerable to cyberattacks, necessitating efficient network intrusion detection systems. Existing machine learning-based NIDS often struggle with numerous irrelevant or redundant features in datasets, which negatively impacts model complexity and accuracy. A research gap exists in comprehensively comparing FS and FE methods, especially on contemporary IoT datasets like TON-IoT, to understand their trade-offs in detection accuracy and computational cost under the same experimental settings.

## Methodology
The research employs a **3-phase machine learning pipeline framework** to compare FS and FE methods:
1.  **Data Preprocessing**: Cleansing, partitioning, and normalization to standardize data format. This includes feature elimination, missing value handling, duplicate removal, non-numerical features encoding, data splitting, and min-max scaling.
2.  **Feature Reduction**: This critical stage employs either FS or FE techniques to identify the most crucial attributes and reduce data dimensionality.
    *   **Feature Selection (FS)**: Uses Pearson correlation coefficient (PCC) to select informative features. Features highly correlated with the target variable and uncorrelated with each other are preferred. Iteratively defined correlation score thresholds are used to select subsets of 9, 22, 33, 47, and 77 (full) features.
    *   **Feature Extraction (FE)**: Uses Principal Component Analysis (PCA). PCA is applied on both training and test data to transform high-dimensional data into lower-dimensional representations. The number of components extracted matches the number of features selected by FS for comparison. PCA is chosen over Autoencoders to mitigate higher computational complexity and latency.
3.  **Classification Modeling**: Five classic machine learning models, widely utilized in recent NIDS works, are employed for binary and multiclass classification to validate the impact of the two feature reduction methods.
    *   **Models**: Decision Tree (DT), Random Forest (RF), k-Nearest Neighbors (kNN), Naive Bayes (NB), and Multi-layer Perceptron (MLP).
    *   **Hyperparameters**: DT (criterion: Gini, splitter: best, max_depth: None), RF (n_estimators: 100, criterion: Gini, max_depth: 5), kNN (n_neighbors: 3), NB (default), MLP (hidden_layer_sizes: 100, activation: relu, alpha: 0.0001, batch_size: auto, learning_rate: constant, max_iter: 200).

## ML Models Used
*   **Classification**: Decision Tree (DT), Random Forest (RF), k-Nearest Neighbors (kNN), Naive Bayes (NB), Multi-layer Perceptron (MLP).
*   **Feature Reduction**: Correlation-based Feature Selection (FS) using Pearson correlation coefficient; Principal Component Analysis (PCA) for Feature Extraction (FE).

## Datasets Used
**TON-IoT Network dataset**: Specifically, the "Train_Test_Network.csv" subset, which comprises 461,043 records. It originates from heterogeneous data sources (IoT/IIoT sensors, Windows/Ubuntu network traffic). It contains 45 original features across Connection, Statistical, DNS, SSL, HTTP, Violation, and Labeling groups. Target classes include binary (normal/attack) and ten categories (normal and nine attack types: Backdoor, DDoS, DoS, Injection, Password, Ransomware, Scanning, XSS, MITM).

## Preprocessing
*   **Feature Elimination**: Removed identifier features like `ts` (timestamp), `src_ip`, `src_port`, `dst_ip`, `dst_port` to ensure model generalization, leaving 38 features.
*   **Missing Value Handling**: "–" values were replaced with "n/a" and treated as new categorical features (e.g., `service_n/a`).
*   **Duplicates Removal**: 11,071 duplicate rows were removed, resulting in 449,972 unique instances.
*   **Non-numerical Features Encoding**:
    *   One-hot encoding for `proto`, `service`, `conn_state`, `dns_AA`, `dns_RD`, `dns_RA`, `dns_rejected`, `ssl_resumed`, `ssl_established`, `http_trans_depth`, `http_method`, `http_version`, `weird_addl`, `weird_notice`.
    *   Binary encoding for `dns_query`, `ssl_version`, `ssl_cipher`, `ssl_subject`, `ssl_issuer`, `http_uri`, `http_user_agent`, `http_orig_mime_types`, `http_resp_mime_types`, `weird_name`.
    *   This process increased the feature count from 38 to 77.
*   **Data Splitting**: Stratified splitting with an 80:20 ratio for training and test sets, respectively, to maintain class distribution and avoid data leakage.
*   **Normalization**: Min-max scaling (0 to 1) was applied to normalize the data.

## Evaluation Metrics
*   **Classification Performance**: Accuracy, Precision, Recall, F1-score, Matthews Correlation Coefficient (MCC).
*   **Model Efficiency**: Feature Reduction Time, Model Training Time, Inference Time (per data sample, in milliseconds).
*   Confusion matrices were also used.

## Results
*   **FS vs. FE Performance**:
    *   FE generally delivered better classification performance than FS, especially with smaller numbers of features (9, 22, 33, and 47). This advantage was most pronounced for 9 and 22 features.
    *   As feature count approached the full set (77), FS (particularly with RF) could surpass FE (FS-RF: 88.22% Acc, 87.69% F1; FE-RF: 87.04% Acc, 86.14% F1 for 77 features).
*   **Model Preferences**:
    *   FS favored DT (9 features), then MLP (22, 33, 47 features), and finally RF (77 features).
    *   FE initially favored DT (9 features), transitioned to MLP (22 features), peaked with kNN (33 features), and then preferred RF (47, 77 features).
*   **Runtime Performance**:
    *   Feature reduction time: FE (PCA) was generally faster than FS (correlation-based), especially with fewer features, because FS requires extra computational resources for correlation score calculation.
    *   Model training time: FS took less time than FE for a small number of features. However, for increasing features, FE training time could be lower for kNN, NB, and MLP.
    *   Inference time: FE generally showed consistent superiority in minimizing inference time, with DT being the optimal classifier for both methods. kNN had the shortest training time but significantly prolonged inference time.
*   **Class-wise F1-score**: F1-score for normal traffic was significantly higher than for attack traffic due to class imbalance (which was not the focus of this work).
*   **Multiclass Classification**: Performance was significantly lower than binary classification (e.g., 9-feature FE-DT: 77.04% Acc, 40.66% F1).
*   **Conclusion**: The study provides guidelines for selecting appropriate feature reduction techniques based on IoT system constraints and intrusion detection requirements.

## Limitations
*   The study acknowledged that class imbalance handling was not the primary focus, which impacted the class-wise F1-scores, particularly for attack traffic.
*   The effectiveness of FE gradually diminishes relative to FS as the number of features increases.
*   The optimal feature reduction strategy (FS vs. FE) and preferred classifier vary depending on the number of features and desired performance metrics (accuracy vs. runtime).

## Future Work
The paper suggests its findings will provide data-driven insights to guide the selection of feature reduction methods. Implicitly, further work could explore optimizing class imbalance handling and applying these guidelines to broader IoT scenarios.

## Research Gaps Identified
*   Lack of comprehensive comparative studies between feature selection and feature extraction methods, especially for modern IoT datasets.
*   Insufficient evaluation of the trade-offs between detection accuracy and computational complexity under the same experimental settings for FS and FE.
*   Overlooked comprehensive comparison and recommendations using heterogeneous IoT datasets like TON-IoT.

## Relevance to Agricultural IoT IDS
**Highly relevant**. This paper's in-depth comparative analysis of feature selection (FS) and feature extraction (FE) methods, particularly for lightweight NIDS in IoT environments, is crucial for AgriIoT. Resource-constrained AgriIoT devices demand efficient and fast intrusion detection. The findings on trade-offs between accuracy, computational cost, and inference time (down to milliseconds) provide direct guidance for designing effective AgriIoT IDS. The use of a heterogeneous IoT dataset and the explicit consideration of feature reduction techniques to meet IoT constraints makes this study exceptionally valuable for our project's goal of identifying suitable ML approaches for AgriIoT.
